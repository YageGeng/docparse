# 字符恢复与清理设计

## 目标与授权范围

用户要求引入上一轮对照中 liteparse 的全部字符处理能力：AGL 字形名、字体可信度、反向 cmap、连字、可注入轮廓识别及磁盘字形库、标点归一化、输出空白与断词清理、列表符号识别。保留已有圆圈恢复与叠加合成，补齐 RTL 字符范围。用户已明确授权实现；不创建 commit、SubAgent 或 worktree。

## 数据流

- Native 提取按字体判断映射可信度；依次尝试通用 AGL、嵌入字体 Unicode cmap、调用方提供的轮廓识别器。圆圈名称并入同一名称表，使用统一的“明确非 ASCII 符号名称修复 ASCII 回退”规则；已有有效非 ASCII 字符及无可见几何的空白继续保留。
- 字形结果允许多个字符；每个源字形只贡献一次几何、字符编码及字宽，文本和表格词范围包含完整展开结果。只有相邻 PDFium 记录组成完整展开序列并共享字符编码与文本对象时才抑制重复展开，不能仅凭字符串包含原字符判断。
- 引入 liteparse 的 SOH/STX、六种控制码连字及拉丁展示形式展开，标点统一为 ASCII。修复原因记录在 repair_actions；恢复成功的映射不再计为未恢复错误。
- 标点与连字处理作用于 native 提取。OCR 保留供应商文本，与 liteparse 路径一致。不重新引入 normalized_text 或几何空格推断。
- Markdown 语义输出合并正文行、折叠空白并按“字母- + 小写延续”去断词，处理相邻正文块的断词延续；Raw 输出保留物理行。表格、算法和公式不进行正文去断词。
- 纯文本输出按页清理 NUL、上下空行与共同左缩进，保留页分隔符。Markdown 列表识别扩大符号集合并保留原始标记。
- 原始 TextItem、Line、Block 的归属及稳定 ID 不改变；展示层去断词不改变 canonical 文本和来源范围。圆圈几何合成不依赖恢复来源，可以跨字体，但不得跨 MCID、方向或水印边界。

## 组织边界修订

- ResolvedGlyph 统一完成原生字符与名称、cmap、轮廓候选的归一化及修复记录；SegmentBuilder 仅执行分段、源空白和几何累计，并根据已生成的修复标记处理控制字符及编码连字符。
- 字体缓存保存未经归一化的名称、cmap 和轮廓候选，各阶段按需初始化；当前 Unicode、空间几何和是否采用替换的判断始终在缓存之外。
- text_rules 为提取层、语义层和 renderer 提供无状态文本规则，不依赖字体或语义组装类型。
- tests/common/pdf.rs 统一 PDF 对象、xref、trailer 的序列化，各测试保留自己的页面与字体内容。

## 轮廓数据库

- 公共 GlyphResolver 接收固定 10pt 的字形路径，返回可选字符串；DocParserBuilder 可以注入共享识别器，Native 可通过 DOCPARSE_FONT_DB_DIR 自动装配 FontDbResolver。
- 数据库兼容 liteparse 的 BLAKE3 前 16 字节键与两字节前缀分片，以及 MessagePack [hash, unicode] 记录。按需缓存分片及缺失结果，未知字形继续使用原始回退。
- 文件系统与环境变量访问限定在 wasm_compat，浏览器仍支持注入识别器；没有数据库时全部确定性恢复正常工作。
- 限制字体 cmap 展开规模及数据库记录大小，拒绝损坏输入，不记录完整正文或逐字日志。

## 验证

覆盖 AGL 名称语法及无效名称、真实 PDF 字形修复、连字去重及表格字节范围、cmap 格式与损坏输入、轮廓注入和磁盘分片、标点、正文去断词和 Raw 保留、列表及 RTL。运行 core 测试、workspace 相关检查、WASM 编译及 pre-commit。新增函数及非平凡逻辑使用英文注释。
