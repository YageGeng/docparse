# 资源生命周期背压修复设计

状态：已完成初版和复查修复并验证；详见[实施与验证记录](../plans/2026-10-02-resource-backpressure.md)。

## 目标与范围

依据本次用户明确要求：删除公式水位降级的全部支持；在重型分配前准入；限制服务端解析到结果发布的在途文档；修复取消时的许可归还；保证原生队列公平。上传仍直接持久化排队，不加入解析积压拒绝策略。

在当前检出中顺序实现，不使用 subagent、worktree，不创建 commit。新增代码注释使用英文，本文与实施计划使用中文。

## 方案

1. 删除 `FormulaBackpressureConfig`、压力控制器、计时线程、压力接口、指标、跳过内联公式逻辑和浏览器配置字段。旧字段由现有严格反序列化拒绝，不保留兼容开关；用户显式的 inline/display 开关保留。
2. 使用共享的 RAII `ResourceLease` 承载信号量许可。异步作用域、CPU 工作、页面图像及模型请求共同持有许可；嵌套许可保留父资源，取消等待者不提前回收实际资源容量。复用 Tokio 信号量和现有 CPU/页面所有权边界，不增加依赖。
3. Layout 在张量预处理前获取全局许可，预算为 session_size × batch_size + queue_size。OCR 检测使用相同预算，行裁剪/方向/识别使用全局窗口（已启用识别和方向模型预算的最大值），替代仅每页受限的资源上限。
4. TSR 分别限制表格图片与每次预测新建的张量，两种预算均取结构与启用的单元格模型预算最大值。core 在裁剪前取得图片许可；每次 predict 独立取得张量许可，因此共享图片不会绕过推理准入，也不会重复占用裁剪许可。表格提供者使用 ResourceBudget 同时提供固定窗口与共享许可，未提供时才使用 parser 的配置预算。
5. 公式沿用现有裁剪前准入容量，但许可进入资源作用域，跟随图像、CPU 操作、实际模型请求释放，删除仅由等待方持有的生命周期漏洞。
6. 服务端 Worker 在领取任务前获取共享文档许可，覆盖预扫描、整本文档结果、序列化、存储发布和完成确认；真实后台任务继续保留许可。文档预算取 render.workers + render.queue_size，允许所有渲染进程与未完成页面重叠，避免回到单进程串行处理整本文档。达到上限只暂停 Worker 领取，不影响上传。
7. 原生队列以 Tokio FIFO 信号量分配待消费槽位，原有 Condvar 只唤醒消费者；出队归还许可定向唤醒生产者，关闭时统一唤醒。保留同步与异步入口及原子批量准入，正常路径不广播生产者。

## 保证与边界

- 队列的待消费上限和已有批处理语义不变；容量预算覆盖预处理、等待、执行、取消清理，不因取消额外发放资源。
- 文档预算限制同时持有的文档数量，单本文档的完整结果仍与文档大小成正比。现有完整 DocumentResult API 不改成流式输出，不宣称任意输入下固定字节数的 RSS 上限。
- 直接调用方在传入 API 前分配的输入，以及调用方自行缓存的返回结果，仍属于调用方资源管理。
- 正常路径保持预处理与推理重叠；不开定时轮询，不增加依赖，不通过丢弃模型工作降低负载。

## 验收

- 旧配置在文件、环境覆盖和浏览器反序列化层拒绝；不存在运行中的压力策略或残留指标。
- 满容量时下一个裁剪/预处理不能开始；不同页面与文档共享预算。
- 取消后真实 CPU/模型/图片持有者退出前不能重新取得许可。
- 文档已解析但尚未发布时，领取预算仍被占用；上传原有测试保持通过。
- 旧生产者先取得新释放的槽位；取消/关闭不会丢失许可或让等待者永久挂起。
- 运行受影响测试、格式检查、clippy、平台边界检查和 WASM 编译；比较原生队列正常路径与竞争路径的开销。

## 复查修订

- TSR 的图片存活预算与每次推理的张量预算分开，每次 predict 都取得独立的张量许可；删除通过图片租约身份跳过准入的逻辑。
- 表格提供者返回包含固定容量与信号量的 ResourceBudget。窗口与许可来自同一对象，parser 配置只提供缺省预算。
- 外部识别使用一个 timeout，覆盖裁剪准入、裁剪 CPU 排队/执行、模型预处理和调用。裁剪只捕获块 ID 与边界等轻量信息，原始 Block 留在调用方，以便超时立即恢复源文本。规则阶段与识别成功后的回填仍属于页面 CPU 阶段，受文档级监督；不将表格识别超时表述为整个页面完成时限。
- TableContext 分担外部识别与结果回填，Worker 分开监督、解析、序列化发布、完成确认，OCR 分开页内调度与单行处理。删除结果写入的重复 tracing 上下文包装。
- 不增加依赖、不改变上传策略、不提交 commit，不使用 subagent 或 worktree。
