# 持久化 HTTP 解析与分阶段流水线

## 目标与部署

新增仅面向原生平台的 `docparse-server`，使用 Axum、SeaORM 2.0、PostgreSQL 和所有实例共同挂载的文件目录。上传完成返回任务 ID；浏览器连接不拥有解析任务。API 和 Worker 可在同一进程运行，也可分开部署。共享目录必须支持跨实例读取、原子重命名与持久化同步，不能使用各容器独立的临时目录。

## HTTP 契约

- `POST /jobs`：multipart 的唯一 `file` 字段为 PDF，必需 `Idempotency-Key`（UUID），成功返回 `202` 和 ApiResponse 任务快照。同一键、同一文件返回原任务；同一键、不同内容返回 `409`。先持久化文件，再提交数据库，之后才确认接收。
- `GET /jobs/{id}`：返回状态、当前尝试次数、最新进度和版本号。
- `GET /jobs/{id}/events`：SSE 首次连接及重连返回最新快照，后续按版本发送变化；事件 ID 为数据库版本号。终态发送后关闭。快照允许合并中间进度，终态及最终 JSON 始终可单独查询。
- `GET /jobs/{id}/result`：成功时流式返回 ApiResponse<DocumentResult> JSON，未完成返回 `409`，未知任务返回 `404`。
- `GET /health`：存活检查；`GET /ready`：数据库和共享目录可用且实例未退出。

服务默认监听本机；鉴权由部署入口承担，任务 ID 不作为多租户授权机制。限制请求大小、同时上传数与上传时间。错误响应不包含数据库地址、文件路径或凭据。原文件名不参与磁盘路径构造。

## 持久化与恢复

PostgreSQL 同时充当任务队列和唯一状态来源。独立 migration 通过 sea-orm-cli 生成后编辑，仅使用 SeaQuery 创建表和索引；database 存放 CLI 生成的 entities 与 query，使用 thiserror；server 按 WisLand 分层适配 ApiResponse/APICODE，只有 server 使用 Snafu。Worker 用 `FOR UPDATE SKIP LOCKED` 原子领取排队或租约过期的任务。每次领取增加尝试次数与版本，分配新的租约令牌；进度、心跳和结果提交均检查令牌及有效租约，拒绝旧 Worker 覆盖新尝试。

默认租约 60 秒、最长心跳间隔 20 秒、最多 3 次尝试。租约过期后可重新执行；达到上限转为失败。SSE 断开不影响任务。SIGTERM 停止领取任务并等待在途任务完成；超出部署退出宽限期的任务通过租约恢复。Worker 故障恢复为整份 PDF 重试，不承诺页级检查点或恰好执行一次。最终结果采用每次尝试独立文件，写入、同步、原子重命名后才提交成功状态。

输入以内容摘要命名，任务 ID 由客户端幂等键确定。无自动删除已接受的输入和结果；未提交的临时文件及崩溃遗留文件不作为任务结果暴露，部署时可清理确定未引用的历史文件。重试执行当前 Worker 部署的模型与配置，滚动发布必须保持配置兼容。

## 解析流水线

保留全文预扫描和全局水印/字体统计，以保持结果语义。之后拆分为有界的渲染、Layout/文本准备、OCR/文本合成、TSR/完成四个阶段。每个分析阶段最多 `runtime.page_concurrency` 页，渲染队列继续使用 `runtime.render_queue_capacity`。容量满时产生背压，避免无限积累页图；不同阶段允许同时推进。

PDFium 继续保持进程级安全串行。最后一页渲染并交付后立即关闭文档，不再等待 OCR/TSR 全部结束。CPU 文本合成和验证在原生 blocking executor 运行，浏览器沿用已有兼容层。内置 OCR 新增 `max_in_flight`（默认 2，浏览器仍为 1），允许一页识别时另一页检测，模型 Session 仍各自串行且持有输入至实际推理结束。

HTTP 队列与 GPU 吞吐是不同问题：增加副本需配合独立 GPU 或明确显存预算。现有 Layout Session 池和各模型计时用于实测调参；不承诺未经测量的 GPU 利用率，不引入批处理模型改造。

## 验收

1. 人为阻塞 OCR 时后续页仍能进入 Layout；TSR 阶段不会占据 OCR 阶段名额。
2. 首文档等待推理时，完成渲染后其他文档可以打开 PDFium；失败和取消不会遗留持锁 Worker。
3. 两个 API 实例共享状态，重复上传保持同一任务，SSE 重连可读最新终态及 JSON。
4. 两个 Worker 不会同时合法领取同一租约；租约到期可接管，旧令牌不能更新进度或提交结果。
5. 原生相关测试、Clippy、WASM 边界检查与浏览器构建通过；真实模型 CPU 验证可运行，GPU 指标仅在设备可用时报告。
