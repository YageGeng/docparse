# 正文列表恢复实施计划

**目标：** 在现有解析流程中恢复正文的有序、无序、嵌套列表与续行，并同步 JSON、Markdown 和 Web 内容展示。

**用户确认的范围：** 仅 `LayoutLabel::Text` 使用列表恢复。目录 `Content`、算法 `Algorithm`、图表 `Chart` 以及其他所有布局类型直接跳过。保留原始文字、TextItem ID 和坐标，列表只建立非拥有引用。

**实施约束：** 在当前目录执行，不创建 worktree，不提交或部署；Rust 非平凡逻辑及新增函数使用英文注释；结构类型遵守 typed-builder 和 utoipa 约定。CPU 逻辑复用现有 PageAnalyzer 的隔离执行路径。

## 步骤

- [x] 先通过真实 PageAnalyzer 的回归复现缺失的列表结构和 Markdown，再实现正文识别、标记族、连续性确认、层级及续行归属。
- [x] 增加可选 `Block.list_items`，保留标记、编号、组号、层级、原始行引用及首行标记结束位置；补全校验器和手写 JSON 投影。
- [x] 统一公式与列表的 Markdown 投影，正文中的无序符号规范为 `-`，有序标记规范为数字，同时在 JSON 保留原标记；目录、算法、图表保持原输出。
- [x] Web 内容页复用 Markdown 渲染，公式详情依据实际公式而不是 Markdown 是否存在；重新生成 API 类型并补充列表样式。
- [x] 运行列表、公式、布局、JSON、OpenAPI 回归及 clippy、WASM、前端构建；具备真实 app 后端时验证浏览器显示。

## 识别与兼容规则

- 显式数字标记支持 `1.`、`2)`、`(3)`、`4、`；符号支持现有圆点、方块、短横线和星号。
- 字母和罗马编号需要连续同类序列；裸数字需要至少三个从 1 起连续、几何一致的条目，避免年份、页码和普通数字句被吞入列表。
- 在块内及相邻正文布局之间恢复列表；不跨页拼接，非 Text 布局和分栏是硬边界。已确认的跨块列表合并后重建父级限定的 LineId，原始 TextItem 及其文字、坐标保持不变，序列化隐藏被吸收的旧布局框。
- 嵌套依据实际缩进栈，续行结合字体、行距和正文起点；保留普通段落与列表之间的边界。
- 不依赖 HTML 列表标签，输出 CommonMark 支持的列表语法；列表正文继续经过公式替换和字面文本转义。
- 旧 JSON 缺少列表字段时按空列表读取；缓存版本更新不会给历史 JSON 自动补充列表结构，新结构由重新解析产生。
