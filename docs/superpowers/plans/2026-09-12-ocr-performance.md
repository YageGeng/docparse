# OCR 性能与组织审查计划

- [x] 建立 release 基准，测量页面准备、原生/OCR 合并和词间空格处理。
- [x] 将 OCR 触发判断收拢到 OCR 模块，每页只分类一次原生字符；关闭 OCR 时省略区域搜索。
- [x] 消除单矩形重叠检查的临时容器，保留精确联合覆盖语义。
- [x] 分离词边界处理，缓存字符属性并缩小常见方向的邻居搜索范围；保留一般角度的正确性。
- [x] 对照优化前后结果和基准，补充英文函数与逻辑注释。
- [x] 执行测试、Clippy、pre-commit、生产 Web 构建与真实浏览器端到端验收。

不创建 commit、worktree，不使用 SubAgent。模型推理与 GPU 同步边界保持现有契约。

结果：release 微基准中的 CPU 热点耗时约降低 17–33 倍；349 项测试、Native/WASM Clippy、pre-commit、Web 构建通过。真实浏览器完成 152 页解析，并验证 OCR 关闭路径。长文档抽查首、中、末页；详见 [英文报告](../../reports/2026-09-12-ocr-performance.md)。
