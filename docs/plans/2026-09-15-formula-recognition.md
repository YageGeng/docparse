# PP-FormulaNet_plus-L 公式识别方案与实施计划

## 范围

按用户已明确的需求，复用 PP-DocLayoutV3 的 `inline_formula`、`display_formula` 检测结果，对所有公式区域批量识别。`formula_number` 保留为原生编号，不送入公式模型。先支持固定的 PP-FormulaNet_plus-L ONNX 与匹配 tokenizer。

JSON 在 `pages[].formulas[]` 中同时输出每条公式的 `latex` 和 `markdown`，以及原检测区域、文本/表格归属和失败原因。Markdown 输出在原文相应位置插入 `$...$` 或 `$$...$$`，避免原生公式字符重复。原生 TextItem、Line、表格文本引用保持不变。公式另外保留 `text_spans`，复用已有词级测量和 UTF-8 字节范围，避免同一文本项中的相邻正文被替换。用户已确认不需要整篇 `.tex` 输出。

## 实现选择

复用本项目的配置、模型校验、推理线程/浏览器 actor 和现有版面结果；新增单一 `docparse-formula` 模型模块。整套引入 oar-ocr 会重复布局/OCR/表格处理，独立 Python 服务则增加部署边界，因此采用现有 Rust/ORT 架构。

- 配置：`formula.enabled`、模型/tokenizer/manifest 路径、`batch_size`、`timeout_ms`。代码默认关闭以兼容显式模型注入；主配置启用。原生按编译期后端运行；实测 Plus-L 的 CoreML 重复调用不稳定，Apple 构建对此模型使用明确记录的 CPU 兼容执行器，保留真正批量；浏览器沿用 Worker 后端。
- 模型：校验固定 SHA-256，读取真实输入/输出结构。没有概率输出时不制造置信度，不用推理后的截断冒充生成长度限制。
- 调度：按页保留原始公式检测，逐批裁剪；共享一个有界模型会话，限制输入积压。超时或模型错误必须记录公式失败和页面告警，保留原生内容；不能无声丢弃区域。
- 输出：公式结果只存一份，引用现有块、行范围或单元格坐标。JSON 的配置过滤不能删除公式结果。Markdown 用识别结果替代对应展示范围，失败时保留原生文本/占位符。
- 平台：原生复用 `SessionWorker`，浏览器复用已有 actor + 全局推理/读回锁，显式传递公式模型和 tokenizer 字节。
- API：同步 OpenAPI/TypeScript 结构；按已有输出选择扩展结果获取方式，JSON 始终保留两种公式表示。

## 验收

1. 每个被选中的公式检测都有成功或明确失败结果，数量与检测输入可核对。
2. 成功 JSON 同时含非空 LaTeX 和对应 Markdown；行内、行间分隔符准确，公式编号不进入识别。
3. Markdown 中相邻正文和表格内容不丢失，原生公式字符不重复输出；JSON 中原生来源可追溯。
4. 批量输入保持结果顺序、尾批次不丢样本，异常不伪装成功，超时不释放仍在执行的输入内存。
5. 模型、tokenizer、后端和测试文档版本可复现；真实模型性能单独记录预热、推理、解码与整篇耗时。
